# Mobile-App — gleiche Plattform, gleiche Regeln

Die **Mobile-App** (`mobile`, bare React Native 0.86, kein Expo) ist ein **gleichwertiges Frontend derselben FastAPI** (`/api/v1`) wie Web und Plattform — die All-in-One-App mit **vier Erlebnissen**: Gast · Agentur · Owner · Mitarbeiter. Das aktive Erlebnis kommt aus dem Konto (Rolle), nicht aus einer Client-Entscheidung. Es gibt **zwei strikt getrennte Auth-Welten**: Tenant-Nutzer (Agentur/Owner/Mitarbeiter) vs. `portal_guests` (Gäste).

Anzeigename auf dem Gerät: **My Next Day**. Alle Daten laufen NUR über `mobile/lib/api.ts` (Bearer aus Keychain) — kein direkter Supabase-Zugriff außer Realtime.

</De>

# Mobile app — same platform, same rules

The **mobile app** (`mobile`, bare React Native 0.86, no Expo) is an **equal frontend of the same FastAPI** (`/api/v1`) as web and platform — the all-in-one app with **four experiences**: guest · agency · owner · staff. The active experience comes from the account (role), not a client decision. There are **two strictly separated auth worlds**: tenant users (agency/owner/staff) vs. `portal_guests` (guests).

Display name on device: **My Next Day**. All data goes ONLY through `mobile/lib/api.ts` (bearer from keychain) — no direct Supabase access except realtime.

## Zwei Auth-Welten & Token-Handling

Tenant-Login (Agentur/Owner/Mitarbeiter) und Gast-Login (`portal_guests`) sind strikt getrennt. Tokens (access + refresh) liegen NUR in react-native-keychain — nie AsyncStorage, nie geloggt. Auf 401 folgt **genau EIN** Refresh-Versuch (single-flight), sonst Logout; das Auth-Rate-Limit ist 10/60/IP (Wurzel 2, Doppelanfragen).

## Two auth worlds & token handling

Tenant login (agency/owner/staff) and guest login (`portal_guests`) are strictly separated. Tokens (access + refresh) live ONLY in react-native-keychain — never AsyncStorage, never logged. A 401 triggers **exactly ONE** refresh attempt (single-flight), otherwise logout; the auth rate limit is 10/60/IP (root 2, duplicate requests).

<Mermaid
  title="Login, token refresh & realtime"
  chart={`sequenceDiagram
    actor U as User/Guest
    participant APP as App (lib/auth.ts)
    participant KC as Keychain
    participant API as FastAPI /api/v1
    participant RT as Realtime (Kong)

    U->>APP: Login (tenant OR portal_guest)
    APP->>API: POST /auth/login (10/60/IP)
    API-->>APP: access + refresh
    APP->>KC: store tokens (never AsyncStorage/log)
    APP->>API: GET /auth/me (role/capabilities)
    Note over APP: choose experience (guest/agency/owner/staff)
    APP->>RT: setAuth(access) BEFORE subscribe()
    API-->>APP: 401 (token expired)
    APP->>API: exactly 1 refresh (single-flight)
    alt Refresh ok
        API-->>APP: new access token
    else Refresh failed
        APP->>KC: clear tokens → logout
    end`}
/>

## UI-Kit & Theme

Die App teilt ein eigenes UI-Kit (`components/ui/kit.tsx`) auf Basis von Design-Tokens (`theme/tokens.ts`, Light/Dark, Akzent, Dichte). Die Bausteine — Txt, Btn, Chip, Card, Badge, Segmented, Toggle, Progress, Photo, Avatar, ListingCard … — sind einzeln im Storybook-Bereich **Mobile-App/UI** dokumentiert.
