**An:** support@nextpax.com
**Betreff:** Partner-Anfrage: White-Label-PMS-Plattform sucht Supply-API-Anbindung (Property-Onboarding inkl. Booking.com)

Sehr geehrtes NextPax-Team,

wir sind **myNextDays**, eine White-Label-Buchungs- und Property-Management-Plattform
(PMS) für Unterkunftsanbieter. Wir sind **kein einzelnes Hotel**, sondern eine
Software-Plattform, die ihre Anbindung **einmal** integriert und darüber die
Unterkünfte vieler Mandanten verwaltet und an OTAs verteilt.

Aktuell nutzen wir einen Channel-Manager, der bestehende OTA-Unterkünfte zwar
verbinden, aber **keine neue Unterkunft bei Booking.com von Null anlegen** kann.
Genau das ist unser Ziel: Unser Kunde legt eine Unterkunft in unserer Plattform an,
und diese soll über eure **Supply API** automatisch bei den verbundenen Portalen
(Booking.com, Airbnb, Vrbo/Expedia) erstellt und verteilt werden.

Damit wir prüfen können, ob eine Partnerschaft für uns passt, hätten wir folgende Fragen:

1. **Property-Erstellung von Null:** Kann über die Supply API eine **brandneue**
   Unterkunft bei Booking.com angelegt werden (inkl. Content, Rate-Plans,
   Verfügbarkeit), ohne dass die Unterkunft vorher manuell im Booking.com-Extranet
   existieren muss? Stellt NextPax dabei auch den Booking.com-Vertrag aus?

2. **White-Label:** Können wir die Supply API vollständig white-label betreiben,
   sodass unsere Endkunden ausschließlich unsere Oberfläche sehen und „NextPax"
   nirgends in Erscheinung tritt?

3. **Mandantentrennung:** Können wir pro Kunde/Mandant einen eigenen
   `propertyManagerCode` (oder vergleichbar) anlegen, sodass die Unterkünfte sauber
   je Mandant getrennt sind?

4. **Mindestvolumen & Einstieg:** Mit wie vielen Unterkünften können wir **starten**?
   Gibt es eine Mindest-Property-Zahl, um die Supply API als Plattform-Partner zu nutzen?

5. **Pricing:** Wie sieht das Preismodell für einen White-Label-PMS-Partner aus
   (Pay-per-Booking, pro Unit/Monat, Grundgebühr)?

6. **Sandbox & Onboarding:** Gibt es eine Test-/Sandbox-Umgebung für die Integration?
   Wie läuft der Onboarding-Prozess als Plattform-Partner ab und wie lange dauert er
   typischerweise?

7. **OTA-Abdeckung & manuelle Schritte:** Welche Portale deckt ihr ab, und welche
   Schritte bleiben pro Unterkunft manuell (z. B. Foto-Upload, Vertragsbestätigung,
   Payments-Aktivierung)?

Über eine Einschätzung und gerne ein kurzes Gespräch würden wir uns sehr freuen.

## English Version

**To:** support@nextpax.com
**Subject:** Partner inquiry: White-label PMS platform seeking Supply API integration (property onboarding incl. Booking.com)

Dear NextPax team,

We are **myNextDays**, a white-label booking and property management platform (PMS)
for accommodation providers. We are **not a single hotel** but a software platform
that integrates once and manages/distributes the properties of many tenants through
our system.

We currently use a channel manager that can connect existing OTA properties but
**cannot create a brand-new Booking.com property from scratch**. That is exactly our
goal: our customer creates a property in our platform, and it should be automatically
created and distributed to the connected portals (Booking.com, Airbnb, Vrbo/Expedia)
via your **Supply API**.

To evaluate whether a partnership fits us, we have the following questions:

1. **Property creation from scratch:** Can the Supply API create a brand-new property
   on Booking.com (content, rate plans, availability) without it first existing
   manually in the Booking.com extranet? Does NextPax also issue the Booking.com
   agreement?
2. **White-label:** Can we run the Supply API fully white-label, so our end customers
   only see our interface and "NextPax" never appears?
3. **Multi-tenancy:** Can we create a separate `propertyManagerCode` (or similar) per
   customer/tenant for clean separation?
4. **Minimum volume & entry:** How many properties can we **start** with? Is there a
   minimum property count to use the Supply API as a platform partner?
5. **Pricing:** What does the pricing look like for a white-label PMS partner
   (pay-per-booking, per unit/month, base fee)?
6. **Sandbox & onboarding:** Is there a test/sandbox environment? How does partner
   onboarding work and how long does it typically take?
7. **OTA coverage & manual steps:** Which portals do you cover, and which steps remain
   manual per property (e.g. photo upload, contract confirmation, payments activation)?

We would greatly appreciate your assessment and a short call.
