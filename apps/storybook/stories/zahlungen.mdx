# Zahlungen & Stripe Connect

Dokumentation der Zahlungsinfrastruktur von NextDays. Primäres Gateway ist **Stripe Connect Custom** — Gastgeber werden vollständig White-Label auf unserer Plattform onboardet, Gäste zahlen direkt an NextDays, die Auszahlung an den Gastgeber erfolgt automatisch abzüglich der Plattformgebühr.

> ADR: [ADR-0011 — Stripe primär](https://github.com) · [ADR-0003 — superseded](https://github.com)

---

## Architekturentscheidung

**Stripe Connect Custom** wurde gegenüber Express/Standard gewählt, weil:
- Vollständige White-Label-Kontrolle — kein Stripe-Branding für den Gastgeber
- NextDays übernimmt das KYC-Onboarding (Name, Adresse, Bankverbindung, Ausweisdokument)
- Vollständige Kontrolle über UX und Darstellung

## Implementierte API-Endpunkte

| Methode | Pfad | Beschreibung |
|---------|------|--------------|
| `POST` | `/api/v1/payments/connect/accounts` | Stripe Custom Account + Onboarding-Link erstellen |
| `GET` | `/api/v1/payments/connect/accounts/{id}` | KYC-Status abfragen |
| `POST` | `/api/v1/payments/connect/accounts/{id}/onboarding-link` | Neuen Onboarding-Link generieren (nach Ablauf) |
| `POST` | `/api/v1/payments/webhook` | Stripe-Webhook-Empfang (HMAC-verifiziert) |

---

## Webhook-Handler

Der Webhook-Endpunkt verarbeitet folgende Stripe-Events:

| Event | Was passiert |
|-------|-------------|
| `account.updated` | `tenant_billing_profile` wird mit `charges_enabled`, `payouts_enabled`, `details_submitted` aktualisiert. Bei erstmaligem KYC-Abschluss wird `stripe_onboarding_at` gesetzt. |

**Sicherheit:** Jeder Webhook-Request wird via HMAC-SHA256 (`Stripe-Signature` Header) gegen das `STRIPE_WEBHOOK_SECRET` verifiziert. Ungültige Signaturen → `400`.

---

## Datenbank

Migration `0081_stripe_connect_account.sql` fügt folgende Spalten in `tenant_billing_profile` ein:

| Spalte | Typ | Bedeutung |
|--------|-----|-----------|
| `stripe_account_id` | `text` | Connected Account ID (`acct_...`). NULL = noch nicht onboardet |
| `stripe_charges_enabled` | `boolean` | Konto kann Zahlungen empfangen |
| `stripe_payouts_enabled` | `boolean` | Konto kann Auszahlungen erhalten |
| `stripe_details_submitted` | `boolean` | KYC vollständig eingereicht |
| `stripe_onboarding_at` | `timestamptz` | Zeitpunkt des KYC-Abschlusses |

## Lokales Testen

```bash
# Terminal 1 — API starten
cd apps/api
uvicorn src.main:app --reload --port 8000 --log-level info --reload-exclude '.venv'

# Terminal 2 — Stripe Listener
stripe listen --forward-to http://localhost:8000/api/v1/payments/webhook

# Terminal 3 — Event feuern
stripe trigger account.updated
```

**Erwartetes Ergebnis im Backend-Log:**
```
stripe_webhook_received    event_type=account.updated
PATCH tenant_billing_profile → 200 OK
stripe_account_not_found_in_db  (solange kein echter Onboarding-Account in der DB)
```
