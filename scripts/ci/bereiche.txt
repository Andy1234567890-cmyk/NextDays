# Welcher Prüf-Bereich der CI wird von welchen Pfaden berührt?
#
# Format: bereich|pfad-präfix1 pfad-präfix2 …
#
# Die EINE Quelle dafür, was ein Push in ci.yml auslöst. Vorher lief jeder
# Prüfjob bei jedem Push: eine Änderung an `plattform/app/robots.ts` startete
# den Android-Release-Prüfbau (JDK + Android-SDK + Gradle + APK, ~10 Minuten)
# und blockierte damit die Warteschlange für den nächsten Lauf.
#
# WICHTIG — die Pfade sind KEINE Verzeichnis-Zuordnung, sondern die Antwort auf
# „welche Dateien kann dieser Job überhaupt lesen?". Mehrere Prüfskripte lesen
# quer über den Baum; steht ihre Quelle hier nicht, wird der Job übersprungen
# und der Befund kommt nie. Die Zeilen sind deshalb einzeln aus den Skripten
# abgeleitet, nicht geschätzt — `bereiche-pruefen.sh` hält sie gegen ci.yml
# deckungsgleich, und der wöchentliche Vollauf fängt, was hier fehlt.
#
# Ergänzt ein Skript eine neue Fremdquelle, gehört sie in dieselbe Zeile.

# --- Backend ---------------------------------------------------------------
# Beide Python-Bäume lösen BEIDE Jobs aus: `public-api-kopien-pruefen.sh`
# verlangt 7 Schwesterdateien byte-identisch, eine einseitige Änderung darf
# nicht durchrutschen.
api|apps/api/ apps/public-api/
public-api|apps/public-api/ apps/api/ deploy/public-api/
# Die simulierte Steuerbehörde. `apps/api/` steht bewusst NICHT in dieser
# Zeile: Der Dienst importiert nichts von dort und darf es auch nicht (der
# CI-Schritt „Kein Import aus apps/api" erzwingt das). Eine Änderung an der
# Erzeugung muss die Prüfung NICHT mitziehen — genau darin liegt ihr Wert als
# unabhängige zweite Lesung der amtlichen Vorlage.
dac7-staging|apps/dac7-staging/ deploy/dac7-staging/

# Statische Fallen, die weder tsc noch ruff noch pytest sehen — jede hat einen
# realen Vorfall hinter sich, und alle drei liefen bis zum 10.09.2026 NUR von
# Hand (34 von 67 Pruefskripten liefen nie automatisch):
#   * typografische-quotes-pruefen.py  — ein „ oder ' im String-Literal bricht
#     den Code; in dieser Sitzung selbst passiert (PropertyKartei.tsx).
#   * use-server-exporte-pruefen.mjs   — ein `export const` in einer
#     "use server"-Datei legt die Seite mit 500 lahm, erst in „Collecting page
#     data". tsc und ESLint sehen es NICHT.
#   * dashboard-kacheln-pruefen.mjs    — Backend-Literal, web-Katalog und
#     Kachel-Inhalt muessen deckungsgleich sein.
#   * workflow-schrittbedingungen-pruefen.py — seit 16.09.2026. Ein Schritt,
#     der seine EIGENE Ausgabe abfragt, wird immer uebersprungen und der Job
#     meldet trotzdem Erfolg; `mobile-android-release` hat so eine Woche lang
#     nichts gebaut. Deshalb steht `.github/` jetzt in dieser Zeile — sonst
#     liefe die Pruefung ausgerechnet dann nicht, wenn jemand einen Workflow
#     aendert.
# Breite Pfade mit Absicht: alle vier pruefen quer ueber das Repo, ein enger
# Filter waere derselbe blinde Fleck in klein.
statische-fallen|apps/api/ web/ plattform/ gastgeber/ admin/ partner/ builder/ marketing/ scripts/diagnose/ .github/workflows/
